# 架构、安全与工程化

## 企业级 AI Chat 桌面端架构

回答主线：

- 基础框架：Electron 或 Tauri，追求体积和性能时优先考虑 Tauri。
- 状态管理：Zustand 或 Redux Toolkit，管理多轮对话、会话列表、模型配置。
- 本地存储：IndexedDB 存历史记录，SQLite 存结构化数据。
- AI 集成：封装统一 LLM Provider 层，支持切换不同模型厂商。
- 离线能力：PWA 或本地缓存，保证基础 UI 在断网时可用。
- 安全：本地密钥存储、权限隔离、内容安全策略、多窗口通信隔离。

容易说错：

- 不要忽略桌面端安全，尤其是本地密钥、Node 权限和跨窗口通信。
- 不要只讲框架选型，要讲状态、持久化、模型抽象和异常恢复。

## Prompt Injection 防护

正确主线：

- Prompt Injection 是 AI 应用特有的安全风险。
- 前端可以做输入提示、风险标记、展示隔离和输出消毒。
- 核心防线应在后端，包括工具权限隔离、系统提示保护、模型输出校验和审计日志。

面试表达：

- “前端是第一层体验防线，但不是唯一安全边界。真正关键的是后端限制模型能访问什么工具、能执行什么操作，以及对模型输出进行二次校验。”

容易说错：

- 不要只说过滤敏感词。
- 不要认为后端处理了就可以忽略前端展示层的 XSS 风险。

## AI Agent 对前端开发模式的影响

回答主线：

- 从“辅助编写”走向“自主构建”。
- UI 可能从 GUI 转向 LUI，再到 GUI + LUI 混合。
- 前端工程师会更多关注组件协议、状态协议、工具调用协议和 Prompt 编排。
- Agent 可用于自动生成界面、提交修复 PR、分析日志、辅助测试。

注意事项：

- 不要盲目乐观，要说明当前模型在复杂业务逻辑、权限边界、长期状态一致性上的局限。

## AI 前端组件库质量评估

评估维度：

- 交互规范：流式输出、引用展示、停止生成、重试、反馈。
- 安全性：XSS 防护、Prompt Injection 展示隔离、敏感信息保护。
- 性能：长对话、大 Markdown、代码块、公式渲染是否稳定。
- 可访问性：键盘操作、屏幕阅读器、焦点管理。
- 可扩展性：模型 Provider、消息类型、工具调用结果是否容易扩展。
- 工程化：类型定义、测试、文档、主题能力、错误边界。

## Vite 预构建

正确主线：

- 开发环境利用浏览器原生 ESM，源码按需加载。
- 依赖预构建使用 `esbuild`，把 CommonJS 或多文件依赖转换成更适合浏览器加载的 ESM。
- HMR 只更新变更模块，因此开发体验快。
- 生产环境仍主要使用 Rollup 完成打包优化。

容易说错：

- 不要说 Vite 生产环境也完全依赖 esbuild 打包。
