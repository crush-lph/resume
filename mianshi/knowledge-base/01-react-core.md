## 渲染机制

高频问题：

- 从一次 `setState` 到页面更新经历了什么？
- React diff 为什么采用同层比较？
- `key` 的作用是什么？
- Fiber 解决了什么问题？

回答主线：

- 状态更新会创建更新任务。
- React 进入调度和协调阶段，计算新的 Fiber 树。
- render 阶段可以被中断，commit 阶段不可中断。
- 最后把变更提交到真实 DOM。

容易说错：

- Fiber 不要说成“把渲染拆成微任务”。
- 更准确的说法是“把渲染工作拆成可调度的工作单元”。
- Fiber 主要提升交互响应性，不是单纯提升绝对渲染速度。

## 性能优化

高频问题：

- 父组件更新为什么会导致子组件重新渲染？
- 为什么加了 `memo` 仍然重复渲染？
- 大列表如何优化？
- 页面卡顿如何定位？

回答主线：

- 先描述性能问题现象。
- 使用 React DevTools Profiler、Performance 面板定位。
- 区分渲染过多、计算过重、DOM 过多、网络慢。
- 再选择 `memo`、虚拟列表、懒加载、批量更新、缓存等方案。

## 状态管理

高频问题：

- Redux、Context、Zustand 分别适合什么场景？
- 什么时候不需要全局状态？

回答主线：

- Context 适合低频、跨层级共享，如主题、语言、用户信息。
- Redux 适合复杂全局状态、可追踪状态变更、大型团队协作。
- Zustand 更轻量，适合中小型项目或局部复杂状态。
