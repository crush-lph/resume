# 纠错与审核清单

这份清单用于审核后续从公众号、截图或网页里提取的面试资料，避免把不严谨的说法直接背下来。

## 已发现需要修正的点

### 浏览器事件循环

不要这样说：

- 浏览器微任务包括 `process.nextTick`

更稳的说法：

- 浏览器微任务包括 `Promise.then`、`queueMicrotask`、`MutationObserver`
- `process.nextTick` 是 Node.js 环境里的特殊队列机制

### React Fiber

不要这样说：

- Fiber 把渲染拆成微任务

更稳的说法：

- Fiber 把渲染工作拆成可调度的工作单元，让 React 可以中断、恢复和按优先级处理更新

### Token

不要这样说：

- 超过上下文长度后模型会失忆

更稳的说法：

- 超过上下文窗口时，旧内容需要被截断、摘要、检索补充，或者请求会失败

### Grid

不要这样说：

- Grid 一定能减少 DOM 层级

更稳的说法：

- Grid 在复杂二维布局中有时可以减少额外包裹层，但不是必然

### Prompt Injection

不要这样说：

- 前端过滤敏感词就能防 Prompt Injection

更稳的说法：

- 前端可以做第一层体验防线，但核心防护必须放在后端权限、工具隔离、输出校验和审计中

## 新资料审核标准

每条资料进入知识库前先检查：

- 结论是否准确
- 是否区分浏览器和 Node.js 环境
- 是否把“可能”说成了“必然”
- 是否只讲 API 而没有讲业务场景
- 是否忽略安全边界
- 是否能用项目例子解释

## 入库格式

建议新增知识点时使用：

```md
## 题目

### 正确答案

### 常见误区

### 面试追问

### 项目表达
```
