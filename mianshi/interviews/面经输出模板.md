# 面经输出模板

这个模板用于后续新增面经文档，目标是让每份面经都同时满足三件事：

1. 能快速浏览：知道这一轮考了什么。
2. 能深入复盘：知道每道题背后在考什么。
3. 能直接背诵：每题都有一段可说出口的答案。
4. 能体现实操：答案要让面试官听起来像真实做过，而不是只会背概念。

## 文档头部

```md
# 公司名称 + 轮次面经

面试日期：YYYY-MM-DD
岗位方向：例如 React / Next.js 前端
题型特点：例如 基础原理、框架机制、工程化、AI 前端
```

## 总体复盘

建议包含：

- 这轮问题更偏什么。
- 面试官的提问风格。
- 回答策略。

示例：

```md
## 总体复盘

这轮问题更偏框架机制和工程化实战，不只问“是什么”，还会追“为什么”和“真实项目里怎么做”。

回答策略：

- 原理题先讲定义，再讲根因，再讲边界。
- 工程题先讲职责拆分，再讲方案。
- AI 题要讲清流程、可观测和风险控制。
```

## 单题标准结构

每道题按下面结构输出：

```md
## 1. 题目

### 关键考点

- 面试官真正想考的 2-4 个点。

### 短答

一句话或两句话先把核心结论说清楚。

### 详细分析

- 根因是什么
- 常见场景是什么
- 怎么做
- 有哪些边界和坑

### 实操口径

- 真实项目里会怎么落地。
- 具体会拆哪些模块、加哪些状态、埋哪些点、做哪些兜底。
- 可以绑定已有项目：FastMoss、Oumomo、MossCreator、ClawDream。
- 尽量出现具体动作：封装、拆分、轮询、缓存、上报、灰度、回滚、Review、测试。

### 可背答案

> 一段可以在面试现场直接说出口的话。优先使用“我在项目里会/我当时是这样做的”口吻，而不是纯概念解释。

### 注意点

- 容易说错的地方
- 容易夸大或说空的地方

### 可能追问

- 追问 1
- 追问 2
- 追问 3
```

## 适用原则

- 如果题目偏基础原理，`详细分析` 要重点讲根因和边界。
- 如果题目偏工程设计，`详细分析` 要重点讲分层、链路、异常和取舍。
- 如果题目偏 AI / Agent，`详细分析` 要重点讲前端职责、可观测、性能和风险控制。
- 每道题都尽量补 `实操口径`，把知识点落到项目动作上。
- 回答里优先出现“我会先...再...最后...”的操作顺序，少用纯名词堆叠。

## 输出质量要求

- 不只写名词解释，要写“为什么”。
- 不只写方案，要写“什么时候适用、什么时候不适用”。
- 不只写“可以怎么做”，还要写“我实际会怎么做、怎么验证、怎么兜底”。
- `可背答案` 要短而完整，能在 30-60 秒内说出来。
- `可背答案` 要有真实工程质感，尽量包含项目背景、具体动作、验证方式或风险控制中的至少两个。
- `注意点` 和 `可能追问` 一定要有，这两部分最能提高复盘价值。
